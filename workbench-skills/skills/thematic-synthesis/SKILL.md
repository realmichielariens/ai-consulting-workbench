# Thematic synthesis

Synthesis is not a summary of each source in turn. It's building a small
set of cross-cutting themes that only become visible once you read the
sources *against* each other.

## Method

1. **Read every source fully first.** Don't start drafting themes after
   the first one or two sources — a theme that looks solid after one
   interview often looks different once you've read all of them.
2. **Extract observations, tagged by source.** As you read, pull out
   discrete points, each with where it came from. You need this traceability
   later, both to back each theme with real evidence and to catch where
   sources disagree.
3. **Cluster into candidate themes.** Group observations that are really
   pointing at the same underlying issue, even if the sources used
   different words for it (a CFO's "reconciliation headache" and a CIO's
   "no shared master data" can be the same theme).
4. **Require independent backing.** A candidate theme that only one source
   raised is an interesting point, not yet a theme — either find a second
   independent source for it, fold it into a broader theme it's evidence
   for, or leave it as a single-source observation rather than dressing it
   up as a consensus finding.
5. **Look deliberately for contradictions.** Before finalizing, go back
   through the sources specifically asking "where do these people actually
   disagree?" Contradictions are easy to miss because each source sounds
   reasonable on its own — they only show up when you compare. A
   contradiction is often more useful to the reader than another point of
   agreement, because it's exactly what needs a decision.
6. **Write each theme with evidence.** State the theme, then back it with
   at least one direct quote (attributed to its source) and a note on which
   sources support it. If sources disagree on a theme, say so explicitly —
   name the positions and who holds them — rather than blending them into
   a single, softened statement that nobody actually said.
7. **Order by importance, not by source order.** Lead with what matters
   most to the reader's decision, not with whichever interview happened to
   be read first.

## What good looks like

- Every theme is backed by **at least two independent sources** (unless
  the brief says otherwise), with the sources named.
- Contradictions between sources are **named explicitly**: who holds which
  position, not "views varied" or a single averaged statement.
- Themes distinguish **symptoms from root causes** where the sources make
  that possible (for example: several surface complaints that are all
  downstream of one structural issue).
- Quotes are used as **evidence for a claim**, not as decoration — each one
  earns its place by supporting the specific point next to it.
- A reader who has not seen the source documents can tell, from the theme
  write-up alone, what the actual disagreement is and who is on which side.

## Pitfalls

- **Restating each source in turn.** If the output reads like four
  interview summaries stapled together, it isn't synthesis yet — the
  cross-cutting structure is the whole point.
- **Averaging away disagreement.** Turning "the COO wants to wait, the CEO
  wants to move now" into "there are mixed views on timing" throws away
  the most decision-relevant part of the finding.
- **One strong opinion mistaken for a theme.** A single forceful quote can
  feel like a theme; check it has independent backing before treating it
  as one.
- **Technology-first framing.** If the sources were interviewed about pain
  points, ambitions and constraints, keep the themes there — don't drift
  into recommending specific systems or vendors, that's a later step.
- **Silent gaps.** If a topic that matters was never actually covered in
  the sources (rather than covered and found to be a non-issue), say so as
  an open issue rather than staying quiet about it or guessing what the
  answer would have been.
