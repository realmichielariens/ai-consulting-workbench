Five UX shifts I propose

each is shown in 07 Screen concept

Documents get the stage

Assets, items and the plan open as tabs in the main stage, the way documents open in an editor. A deliverable is never read in a side panel.

Right-hand detail panel → stage tab with a version rail and a review bar

The Approach Agent is a rail, not a tab

The conversation stays docked on the right and can be collapsed. It always knows what you are looking at ("Viewing themes.md v2.0"), so "what changed here?" needs no extra context.

Chat / Inbox / Approach tabs → persistent rail with context and an agenda toggle

Home is a Brief, not a canvas

Opening an engagement shows what needs you, with the consequence first ("Synthesis is blocked on 1 answer"), then work in flight, then what was published recently.

Plan canvas with empty detail panel → Brief page with action titles

Every decision takes one action

Questions come with the agent's hypothesis, and one keystroke approves, amends or replaces it. Proposals show the plan diff and its impact on dates and cost.

Free-form answer box → a hypothesis card with Approve · Amend · Replace

Canvas for structure, tracker for status

The BPMN-lite canvas explains the plan. A consultant-style tracker table (Harvey balls, owners, gates) is where you scan progress. Both views show the same data and share the same selection.

Canvas only → canvas ⇄ tracker toggle
02

Exhibit: the workbench should look like a finished client deliverable

Consultants trust work that looks like a finished deliverable: action titles, numbered exhibits, a source under every chart, hairline tables, one disciplined accent. The language borrows that visual grammar, so what agents produce looks board-ready without extra formatting.

P1

Action titles

Headlines state the so-what: "3 decisions block Synthesis", not "Inbox". Labels go in small caps above the headline.

P2

Ink on paper

Cool white paper, navy ink and a single accent. Colour carries meaning (status, change, gate) and is never decoration.

P3

Rules, not boxes

Structure comes from 1px hairlines, a heavy rule under headers, and whitespace. Shadows are only for things that float.

P4

Numbers are first-class

Tabular figures everywhere. Ids in mono. Harvey balls for progress, as on a real tracker.

P5

Source everything

Every agent claim cites its assets and versions, the way an exhibit carries a source line. Click a source to open it.

Default assistant look (what we move away from)
  • Warm cream background, clay-orange accent
  • Soft, rounded, conversational; the chat is the product
  • Answers appear in speech bubbles
  • Few visible numbers, little visible structure
Exhibit
  • Cool paper, navy ink, one cobalt accent (switchable)
  • Crisp and gridded; the work is the product, the agent is staff
  • The agent writes memos with sources, not chat bubbles
  • Trackers, Harvey balls, versions and costs are always visible
